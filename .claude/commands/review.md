코드 리뷰를 수행합니다. 대상: $ARGUMENTS

대상이 없으면 `git status`와 `git diff`(staged 포함)로 변경사항 전체를 리뷰합니다.

## 리뷰 관점

1. **정확성**: 버그, 엣지 케이스, 잘못된 로직, 비동기/상태 처리 오류
2. **타입 안정성**: `any` 사용 여부, 불필요한 타입 단언, Zod 스키마와 `z.infer` 타입 일치
3. **Next.js 16 / React 19**: 서버·클라이언트 컴포넌트 경계, `"use client"` 남용, `cacheComponents` 환경에서의 동적 API 사용
4. **프로젝트 컨벤션**: 한국어 주석, kebab-case 파일명, camelCase/PascalCase 네이밍, 들여쓰기 2칸
5. **UI**: shadcn/ui(Base UI) 규칙 준수(`asChild` 대신 `render`), 반응형, 접근성, 다크 모드
6. **재사용성**: 중복 코드, 컴포넌트 분리 필요 여부
7. **성능/보안**: 불필요한 리렌더링, 번들 크기, 입력 검증, 민감 정보 노출

## 출력 형식 (한국어)

- 심각도별로 구분합니다: 🔴 반드시 수정 / 🟡 권장 / 🟢 제안
- 각 항목은 `파일경로:줄번호`, 문제 설명, 수정 방안(필요 시 코드 예시) 순으로 작성합니다.
- 마지막에 전체 요약과 잘한 점을 간단히 정리합니다.

요청 없이 코드를 수정하지 않고, 리뷰 결과만 보고합니다.
