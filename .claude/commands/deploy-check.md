배포 전 점검을 순서대로 수행하고 결과를 한국어로 보고합니다.

## 자동 점검

1. `git status`로 커밋되지 않은 변경사항과 현재 브랜치를 확인합니다.
2. `npm run lint`를 실행합니다.
3. `npm run build`를 실행합니다 (타입 체크 포함). 실패 시 원인을 분석합니다.
4. 코드에서 다음 항목을 검색합니다.
   - `console.log`, `debugger`, `TODO`, `FIXME` 잔존 여부
   - `any` 타입 사용 여부
   - 하드코딩된 시크릿, API 키, 로컬 URL(`localhost`)
5. 환경 변수: `.env*` 파일이 `.gitignore`에 포함되어 있는지, 코드에서 참조하는 `process.env.*`가 배포 환경에 정의되어야 하는지 확인합니다.
6. `config/site.ts`의 사이트 이름, 설명, URL 등 메타데이터가 실제 값인지 확인합니다.
7. `app/error.tsx`, `app/loading.tsx`, `app/not-found.tsx`가 존재하고 정상인지 확인합니다.

## 수동 확인 안내 (사용자에게 체크리스트로 제시)

- [ ] 모바일/태블릿/데스크톱 반응형 동작
- [ ] 라이트/다크 모드 표시
- [ ] 주요 페이지 및 폼 동작
- [ ] 배포 플랫폼의 환경 변수 설정
- [ ] Node.js 20.9 이상 런타임 설정

## 출력 형식

- 항목별 ✅ 통과 / ❌ 실패 / ⚠️ 확인 필요로 표시한 표를 제공합니다.
- 실패 항목은 원인과 해결 방법을 함께 적습니다.
- 마지막에 배포 가능 여부를 한 줄로 결론짓습니다.

자동 점검 중 코드를 수정하지 않고, 문제만 보고합니다.
